Here is the complete, end-to-end guide to building, locking down, deploying, and hiding your WhatsApp-styled, calculator-disguised, burn-after-reading mobile app on both Android and iOS using Google Antigravity IDE and Supabase—with zero personal servers to manage.

Phase 1: Set Up Supabase & Lock Down Access (5 Minutes)
Supabase gives you a free cloud database, real-time WebSocket updates, authentication, and pg_cron scheduling without renting a server.

Create a Project:

Sign in at supabase.com and click New Project.

Pick a project name, database password, and a region near your users (e.g., Mumbai ap-south-1).

Copy Your API Keys:

Go to Project Settings > API.

Copy the Project URL and the anon public key—you will put these in your .env file.

Disable Public Sign-Ups & Create Only 2 Users:

Go to Authentication > Providers > Email and toggle OFF "Allow new users to sign up". Nobody outside your dashboard will ever be able to register.

Go to Authentication > Users and click Add user twice (once for you, once for the second person).

Copy both User UUIDs from the users table.

Enable pg_cron & Run Your Schema:

Go to Database > Extensions, search for pg_cron, and enable it if it isn't already active.

Open SQL Editor, paste the schema (replacing 'REPLACE_WITH_USER_1_UUID' and 'REPLACE_WITH_USER_2_UUID' with your two actual UUIDs), and click Run.

### 4. DETAILED SCREEN & PRIVACY SPECIFICATIONS

#### Layer 1: Total App Disguise & Intrusion Lockout (`CalculatorScreen.tsx`)
- Render a realistic dark-mode calculator (`0-9`, `.`, `+`, `-`, `×`, `÷`, `%`, `+/-`, `AC`, `=`) with accurate floating-point arithmetic.
- Rolling keystroke buffer of last 8 inputs:
  - `7391=` (when not locked out): clear display and open `AuthScreen` (if unauthenticated) or `VaultListScreen` (if authenticated).
  - `0000=`: clear display and open `DecoyNotesScreen` (harmless offline grocery/errand notes with a top-right "Lock" button).
- **Anti-Intrusion Lockout:** After 3 consecutive failed PIN/unlock attempts in memory, lock out `7391=` for 1 hour so the app behaves strictly as a normal calculator.

#### Layer 2: Strict 2-Person Login (`AuthScreen.tsx`)
- Styled in WhatsApp Dark Mode (`#0B141A` / `#00A884`). Email + password login only (no Sign Up or Forgot Password links).

#### Layer 3: WhatsApp Chat List & Hidden Chats (`VaultListScreen.tsx`)
- Subscribe to Supabase `threads` via Realtime (`INSERT`, `UPDATE`, `DELETE`) and store threads strictly in React state memory (never in `AsyncStorage`).
- **Top Header (`#0B141A`):** `"Chats"` title (`#E9EDEF`, 22px bold), Lock icon (`lock-closed-outline`) to immediately return to `CalculatorScreen`, and three-dot menu (`ellipsis-vertical`) with `"New chat"`, `"Sign out"`, and `"Panic Wipe All Data"` (`#F15C6D` confirmation that deletes all rows in `messages` and `threads`).
- **WhatsApp Pill Search Bar (`#202C33`):** Placeholder `"Ask Meta AI or Search"`. By default show only `is_hidden === false`. Typing exact `9999` reveals all `is_hidden === true` threads under a `"Hidden Chats"` header; clearing search hides them again.
- **Rows & Long-Press Menu (`#1F2C34`):** 50x50 circular avatar with initials + `#00A884` timer badge, title + lock icon, last message preview + `#53BDEB` double ticks, timestamp, and unread pill. Long-press offers:
  1. **Hide / Unhide Chat** (`is_hidden` toggle).
  2. **Set / Change / Remove 4-Digit Chat PIN** (SHA-256 hash stored in `threads.pin_hash`).
  3. **Burn Mode & Timer** (`burn_on_read` toggle + `disappear_seconds` of `10s`, `1m`, `1h`, `24h`).
  4. **Delete Chat**.
- **FAB:** Bottom-right `#00A884` button (`56x56`, `borderRadius: 16`) to create a new thread.

#### Layer 4: Per-Chat 4-Digit PIN Lock (`PinModal.tsx`)
- Intercepts tapping any thread where `pin_hash !== null`. Verifies SHA-256 hash of entered 4 digits against `thread.pin_hash`. Unlocked thread IDs stay strictly in React state memory and re-lock on app lock/background.

#### Layer 5: Offline Queue + Burn-After-Reading + Timers (`ChatScreen.tsx`)
- WhatsApp Dark Mode chat view (`#1F2C34` header, `#0B141A` background with subtle `0.04` opacity doodle overlay, `#005C4B` outgoing bubbles, `#202C33` incoming bubbles, `#2A3942` floating pill input bar, `#00A884` circular send button).
- **Offline Queue Behavior:** When User A sends a message while User B is offline or in another screen, the encrypted row stays in `messages` in Supabase until User B opens this `ChatScreen` (or receives it while `ChatScreen` is active).
- **Burn-After-Reading + Countdown Behavior:**
  - Each thread supports `burn_on_read` (boolean, default `true`) and `disappear_seconds` (`10`, `60`, `3600`, `86400`).
  - When User B (`sender_id !== currentUser.id`) opens/views an incoming message in `ChatScreen` and `burn_on_read` is enabled: mark it read, show it briefly (or start a short burn grace timer like `8s` so User B can actually read it before it burns), and then immediately execute `supabase.from('messages').delete().eq('id', msg.id)` so it is deleted from Supabase and disappears from both screens.
  - Also run a 1-second local timer to remove expired messages (`new Date(msg.expires_at) <= new Date()`) from UI state and a 5-second database cleanup (`DELETE FROM messages WHERE expires_at <= now()`).
  - Show a live countdown badge (`⏱ 08s` or `🔥 Burns after read`) and double checkmarks (`checkmark-done`, `#53BDEB`) on bubbles.

### 5. DATABASE SCHEMA & `pg_cron` AUTO-PURGE (`/supabase/schema.sql`)
Generate `/supabase/schema.sql` containing:
```sql
create extension if not exists pg_cron;

create table if not exists threads (
  id uuid primary key default gen_random_uuid(),
  title text not null,
  is_hidden boolean default false,
  pin_hash text,
  disappear_seconds int default 60,
  burn_on_read boolean default true,
  created_at timestamptz default now()
);

create table if not exists messages (
  id uuid primary key default gen_random_uuid(),
  thread_id uuid references threads(id) on delete cascade not null,
  sender_id uuid not null,
  content text not null,
  read_at timestamptz,
  expires_at timestamptz not null,
  created_at timestamptz default now()
);

alter publication supabase_realtime add table threads, messages;

alter table threads enable row level security;
alter table messages enable row level security;

create policy "Strict 2-user threads access" on threads for all
  using (auth.uid() in ('REPLACE_WITH_USER_1_UUID', 'REPLACE_WITH_USER_2_UUID'))
  with check (auth.uid() in ('REPLACE_WITH_USER_1_UUID', 'REPLACE_WITH_USER_2_UUID'));

create policy "Strict 2-user messages access" on messages for all
  using (auth.uid() in ('REPLACE_WITH_USER_1_UUID', 'REPLACE_WITH_USER_2_UUID'))
  with check (auth.uid() in ('REPLACE_WITH_USER_1_UUID', 'REPLACE_WITH_USER_2_UUID'));

-- Server-side safety net: purge expired messages or unread messages older than 7 days every minute
select cron.schedule(
  'purge-expired-stealth-messages',
  '* * * * *',
  $$ delete from public.messages where expires_at <= now() or created_at < now() - interval '7 days'; $$
);
